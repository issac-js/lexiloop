# v118 内容质量与复核任务交付

## 本次实现

- 本地判分只直接接受精确表达、英美拼写、无歧义空格变化和明确配置的替代表达。
  删除“词都出现就通过”、无条件词形后缀和近似拼写放行。冠词、否定和词序保留。
- 无法由本地确定的英文作答进入语义复核。缓存按句子、中文意思、目标、作答和模型隔离，
  旧 v3 缓存失效。异常、超时、格式错误返回待复核，不自动记错；练习自动写入跳过待复核题。
- `judge-benchmark.json` 是 76 条人工编写的规则安全样本，含已知语义预期；
  离线通过验证本地规则及复核接口约束，不代表生产模型对这些题的正确率。
- 内容复核同时运行最多两条；限流后停止新增请求、降为单并发，用户稍后继续。
  在途任务完成后暂停。按成功词条 ID 保存断点，乱序完成不会在恢复时重做。
- 任务按账号隔离，支持 Web Locks 的浏览器防止同账号跨标签重复运行。
  词条内容 SHA-256、复核规则版本及模型一致，且报告未超过 30 天时才可跳过。
- 结构检查、模型复核、缓存、人工修正保护、移除、失败分开计数；速度取实际请求耗时，
  剩余时间仅作动态参考。总量是启动时本账号的唯一词条快照，不是卡片数或全局词库。
- 报告与建议写入现有 `words.verify_note` 的结构化内容，不新增数据库列；
  用 `updated_at` 条件更新并验证返回行，避免静默写失败或覆盖新内容。
- 词条详情可查看报告、核实来源、编辑释义/词性/搭配/例句、查看修改差异并确认保存。
  保存为 `corrected`，保留最多三次修正前版本。卡片与 FSRS 字段不变。
  词条内容是共享的；编辑页明确说明。模型建议不自动替换原文，不声称已查权威词典。

## 原 WorkBuddy 项目的具体接入要求

必须先在原应用内验证服务端计算、任务触发、凭据托管和用户鉴权入口。不得新建替代应用、
迁移用户、把个人登录凭据放到 runner，或把共享词库直接暴露给匿名任务。

若具备支持能力，沿用同一报告结构与内容指纹，接入以下契约：

1. `enqueue(scope)`：服务器从当前用户的 cards 推导唯一词条 ID，冻结内容版本，
   同账号/范围/版本幂等；不能信任客户端随意传入的 owner 或全局词条 ID。
2. `status(jobId)`：验证归属，只返回该用户任务；包含 completed、failed、skipped、
   active、心跳、限流等待、实际速度与预计剩余时间。
3. `pause/resume(jobId)`：停止领取新任务，在途项结算后暂停；账号退出不改变任务归属。
4. worker：服务端凭据调用模型，默认并发 2、共享限流、有限重试、逐项原子落账；
   用租约及 fencing token 拒绝过期 worker 回写，超时任务可重领但不重复计费/计数。
5. `applyCorrection`：验证报告对应的内容版本，保留人工确认和 before-version；
   人工修正不得被模型任务覆盖。涉及共享词条编辑权限时必须沿用/核实原应用权限。
6. 服务端验收：关闭所有浏览器后任务仍前进；切换设备看到同一进度；worker 中断可恢复；
   重复提交不重复执行；跨账号不能读写；429 能退避；人工修正与生成冲突不能覆盖；
   内容/调度数据库无额外副作用。用隔离账号完成，不以模拟结果代替生产验收。

若原平台不能提供这些入口，保留本版明确标注的前台模式；后续迁移方案需另行明确范围。
