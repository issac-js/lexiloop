# 学习型项目通用设计与验收规范

用户于 2026-11-02 确认采用。本文在 LexiLoop 中生效，结构可复用于其他学习、培训及辅助决策项目；不表示其他项目已同步修改。

## 核心循环

理解结构 → 实践纠偏 → 巩固迁移 → 改进创新。按能力而非固定刷题数量推进，允许回到前一阶段；不把所有用户强制锁在同一线性流程中。

| 阶段 | 产品应支持 | 验收证据 |
| --- | --- | --- |
| 理解结构 | 目标、先修知识、逻辑顺序、因果关系、适用条件、例外与关键节点 | 用户能解释为什么这样做、何时不适用；讲解入口可按需查看 |
| 实践纠偏 | 循序渐进的实操、真实或相近情境、针对具体差异的反馈、尝试修正的机会 | 用户能依据提示修正，而不只是抄答案；分别记录提示下完成与独立完成 |
| 巩固迁移 | 间隔复习、跨时间独立回忆、变换情境、逐步减少提示 | 用户在新情境中仍能独立完成；单次答对、重复原题或完成数量不等于掌握 |
| 改进创新 | 比较方案、说明理由、识别边界、提出改进、验证结果 | 有基线、改进理由、验证证据和适用限制；不要求每次练习都创新 |

## 反馈与交互原则

- 鼓励、引导、启发，同时保持事实和语言标准；不把鼓励做成无条件判对。
- 反馈针对本次具体行为，不评价人格、智力或整体能力。可以肯定可观察到的进步，不作无依据夸奖。
- 区分目标表达已回忆但词形需调整、语法成立的替代表达、明确错误、暂无法判断。
- 反馈顺序：指出已做到的部分（有证据时）→ 一项具体差异及原因 → 可执行的下一步。
- 模型不确定或服务失败不得伪装为确定错误；也不能把未核实的建议称为权威事实。
- 提示、示范、独立回忆分别标识。允许用户核对与纠正系统判断；自评建议不冒充已替用户评分。
- 将学习材料与主操作分层：详情按需展开，核心任务和下一步操作容易找到；兼顾触屏、安全区、键盘和无障碍。
- 允许暂停、调整难度与恢复学习。没有用户证据时，不用羞辱、制造焦虑或虚假紧迫感推动练习。

## LexiLoop 的具体落实与边界

| 能力 | 已有基础 | 后续建设要求 |
| --- | --- | --- |
| 理解结构 | 词条释义、搭配、例句及辨析 | 增加用法之间的联系、适用场景与易混边界；尚未形成完整知识路径 |
| 实践纠偏 | 回忆、填空、选择题、替代表达复核；v122 温和词形反馈 | 持续审查模型误判，补充解释与修正机会；夹具通过不等于模型准确率已验证 |
| 巩固迁移 | FSRS 间隔重复、不同卡片类型 | 增加有质量控制的新情境与减少提示的复练；不能仅凭稳定度认定真实迁移 |
| 改进创新 | 可选造句练习 | 逐步加入表达比较、语域调整和新情境应用；暂未实现完整效果评估 |

此表是设计依据，不代表本次已上线新训练功能。保留原应用、账号、学习历史与 FSRS 状态；不得为套用框架重置进度。

## 每次设计与交付的检查清单

1. 说明本次解决哪个学习阶段的具体障碍；不要求每次改动都覆盖四阶段。
2. 用户能否理解目标、原因与适用条件？未知点和例外是否清楚？
3. 是否有可执行的练习与纠偏路径？判分是否区分明确错误与不确定？
4. 是否区分提示下完成、独立完成与跨情境表现？证据不足时是否避免宣称掌握？
5. 核心操作能否快捷完成，展开资料、键盘与小屏幕是否妨碍下一步？
6. 如涉及改进创新，是否要求理由与验证，而非只奖励新奇？
7. 交付报告分别列出已实现、已验证、未验证与后续计划；不得以理念文档代替功能完成。

## 最终评价问题

用户能否越来越独立地理解、行动、纠错，并在新情境中改进方法？

验收优先关注独立表现、同类错误是否减少、提示依赖是否降低及用户负担。刷题量、连续打卡和完成率只作辅助指标；使用用户数据作效果评估应另行明确范围，不随意新增采集。
