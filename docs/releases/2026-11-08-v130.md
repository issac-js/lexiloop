# v130：具体纠偏与语义辨析

## 已实现

学习阶段：实践纠偏 → 反馈后修正 → 新情境辨析。保留原应用、用户、数据库和首次作答，不重置历史或修改 FSRS 算法。

- 通用复核增加结构化 grammar、meaning、issue、correction、explanation。严格校验枚举、一致性、长度与必要语境；矛盾或无效字段降为待确认，不缓存错误。旧格式回复保持兼容，但没有差异说明的失败不再推荐“忘了”。
- 词形纠偏比较用户作答与模型建议的修正，不再要求用户与参考答案同词根。因此 warrants / deserve 可显示 deserve → deserves。只有单个可识别规则词形变化、中文句意匹配且题目有一个空缺时才显示这类具体词形反馈；不是通过去词尾自动判对。
- 语法成立但与题意有区别的表达，以中性主题色说明区别；合理替代表达继续正向接受。词形建议为“吃力”，未知或解释缺失不替用户推断“忘了”，用户仍自主评分。
- 看反馈后的修正练习可选、默认折叠，只核对反馈中的参考修正；不额外调用模型、不新增 reviews、不改首次答案/判定/计时。corrected_with_feedback 随既有观察 JSON 保存并追加 CSV 列；旧记录留空。它表示反馈后完成参考修正，不是独立回忆成绩。
- 学习页可对有疑问的模型提示主动重新核对，绕过并清除旧缓存；请求中防重复、换卡/账号不串题，失败不重放旧拒绝结论。v8 缓存保存具体反馈，按完整语境隔离。
- 离线新情境练习增加可扩展的 relatedAnswers 辨析结构。introduce 明确解释“介绍认识”与 refer“转介求助”；不冒充完全同义，不计目标命中。所有表外表达会展示本题区别供核对，明确尚未自动判定，保持无模型调用。

## 验收范围

用两个截图及语法、否定、句意冲突、缓存、无效模型回复作为回归。模型响应为离线人工标签夹具，验证处理流程和 UI，不代表生产 DeepSeek 的实际准确率。浏览器与 iOS Simulator 使用隔离 SDK，不代表物理 iPhone或生产写权限。没有本轮生产模型调用、数据库迁移或用户历史改写。
