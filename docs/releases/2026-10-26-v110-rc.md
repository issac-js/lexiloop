## 交付范围

- 新增 `focus-core.js`：从已学习、未暂停、审核通过、有释义的词卡构建训练题池；同一词条按词去重；稳定的单选项次序。

- `index.html`、ES 模块、`sw.js` 统一 v110；发布白名单含 24 个资源。
- `tools/focus-practice.test.js` 与 `tools/browser-check.js` 加入防回归：训练前后 FSRS 卡片、复习日志、统计、后端 RPC 事件均不变。

## 定义范围：认知任务，不是神经科学诊断

主动提取与英文情景任务支持英语学习；信息保持和选择辨析只反映特定任务表现。
本版本不输出前额叶能力分数、不宣称泛化执行功能改善，不根据训练成绩修改 FSRS 记忆模型。

## GitHub 维护者要做的唯一账户操作

1. 打开 `https://github.com/issac-js/lexiloop/actions`。
2. 在过往成功运行的工作流下查看 **Artifacts**，先下载/保留重要的正式回滚 ZIP（尤其当前线上最后一次已确认版本）；**只删除不再需要的旧截图、旧 Xcode 测试产物、过期中间构件**。删除不可恢复。
3. GitHub 官方提示已使用容量的账单统计可能需要 6–12 小时刷新。确认容量恢复后，重新运行本 PR 最新 head SHA 的工作流。
4. 待所有检查和发布制品上传成功后，审核合并 PR #4。不要单纯为了去除红色失败状态而跳过上传步骤。

## WorkBuddy 最终发布（需要原项目会话内的当轮明确授权）

1. 使用 **合并到 main 后的最新成功 CI 工件** `lexiloop-FULL_SHA`，不是未合并 PR 的临时包；下载 ZIP 与 SHA256，确认 `release.json` 内 SHA 与 main 完全一致。
2. 在原 WorkBuddy 项目会话内准备原应用目录，不创建新应用、不修改原云服务绑定、数据库或用户数据。
3. 用户在该 WorkBuddy 会话明确说「发布 LexiLoop v110」后，才更新正式站点 `https://lexiloop-82703.app.workbuddy.host/`。
4. 执行 `python -B tools/verify_deployed.py --url https://lexiloop-82703.app.workbuddy.host/ --sha FULL_SHA` 进行资源只读校验。
5. 再用 **隔离 QA 账号** 核验登录/同步、正式学习与 FSRS、综合训练、可选 AI 反馈、PWA 更新及账号隔离；不使用生产用户记录做破坏性测试。
6. 保存已验收的上一版 ZIP、SHA 与核验记录，确保必要时可按 `docs/DEPLOYMENT.md` 回滚静态资源。
