# v131：先核实学习参考，再评估作答

## 问题与结果

用户的 `The knight would live with his lord` 成立；词条把 liver 教成居住的古体/方言动词，缺少可靠依据。Oxford 当前 liver 条目列出名词肝脏及食用动物肝脏（<https://www.oxfordlearnersdictionaries.com/us/definition/english/liver>）。不能通过强行要求用户记住错误参考来修正这个问题。

本次对应学习设计的“理解结构、实践纠偏”：区分材料错误、用户语法问题、可接受替代表达与无法可靠判断，保留已有学习节奏及 FSRS。

## 实现

- `content-quality.js` 提供原始词条之外的学习视图；不改写原云端 payload。已知 liver 错误动词、明确标注古体/方言/废弃的义项及搭配不进入现代英语练习。只隔离有问题的材料；仍有正确现代内容时照常学习。
- 学习、选择题干扰项、练习场、labs、综合训练及背诵手册使用学习视图；原始备份和修正编辑仍保留原内容。单凭“已复核”或“已人工修正”标签不能绕过已知质量问题。
- 内容复核升级为 content-v3。模型明确指出不地道/语法错误的具体搭配后，报告保存其索引，并绑定完整内容快照。该搭配不再出题，其他可用内容保留。修正内容后旧索引自动失效。v2 报告缓存与旧任务断点不冒充 v3 核验；保留旧进度说明，用户下次启动会按新规则检查全部范围；不自动产生付费模型任务。
- 生成/复核提示不允许以虚构古体或方言解释为不成立用法辩护；生成结果进入规则校验。名词复数不再作为动词变形证据；动词判断覆盖全部义项，避免只看第一义项而误伤常见多词性词。
- 语义复核先返回 reference=valid/invalid/unknown，再独立评估用户句子。缺失参考核验也不得产生确定判分。不可用或未核实参考不写入判分缓存。
- 正式学习遇到参考 invalid/unknown 时只提供“不评分跳过”。不展示为确定答案、不显示 FSRS 评分按钮；跳过不写 reviews、不改调度、不消耗日额度。旧错误判分缓存 v8 升级为 v9。
- 我的 → 内容复核增加已加载词条的本地规则检查清单，不调用 AI。liver 提供有来源的名词修正草稿，经完整原内容/新内容预览后走既有乐观锁保存；保留修改历史，卡片及学习进度不变。

## 验收要求

- 离线质量用例覆盖错误 liver 动词、正确 liver 名词共存、现代常见词性转换、罕见用法范围、旧/畸形报告、报告与内容绑定、修正草稿不改变原对象。
- 判分用例覆盖 invalid/unknown/缺失 reference 不判错或写负面缓存，以及 reference 有效仍需单独核对用户语法。
- Chromium/WebKit 增加真实 UI 的无评分跳过与 liver 修正保存检查；Simulator Safari 增加无评分跳过检查。均使用隔离合成 SDK，不能称为生产网关或物理 iPhone 测试。
- 必需检查：`python -B tools/ci_check.py`、`python -B tools/check_line_endings.py`、三个最终提交 CI job。具体结果以关联 PR/main Actions 为准。
